# 接口使用说明

基础地址为 `http://localhost:8080`。以下示例在项目根目录使用 PowerShell 7 执行，默认服务已通过 Docker Compose 启动并初始化演示工具。

## 1. 登录

```powershell
$base = 'http://localhost:8080'
$login = Invoke-RestMethod "$base/api/auth/login" -Method Post -ContentType 'application/json' -Body '{"username":"admin","password":"admin123"}'
$headers = @{Authorization="Bearer $($login.token)"}
```

后续受保护接口携带 `Authorization: Bearer <JWT>`。默认 JWT 有效期为 24 小时，可用 `JWT_TTL_HOURS` 调整；过期后重新登录。

## 2. 浏览和接入工具

```powershell
# 匿名可浏览；sort=popular 按调用热度排序
$market = Invoke-RestMethod "$base/api/marketplace/tools?sort=popular&limit=20"
$market.items | Select-Object id,name,category,version,call_count
$tool = $market.items | Where-Object name -eq 'weather_current' | Select-Object -First 1
Invoke-RestMethod "$base/api/tools/$($tool.id)/versions"
Invoke-RestMethod "$base/api/tools/$($tool.id)/comments"
# 仅为当前登录用户授予该工具的 invoke 权限
$connect = Invoke-RestMethod "$base/api/tools/$($tool.id)/connect" -Method Post -Headers $headers
$connect.config | ConvertTo-Json -Depth 10
```

返回的配置包含 `/mcp` 地址与 JWT 占位符，需要替换为自己的令牌。客户端须支持 HTTP MCP、自定义 Authorization 请求头和本项目协议；不同客户端配置格式可能需要调整。模板中的 localhost 地址应按实际部署修改。

## 3. 通过 REST 调用

```powershell
$payload = @{tool_name='weather_current';arguments=@{city='东莞'}} | ConvertTo-Json -Depth 10
$result = Invoke-RestMethod "$base/api/gateway/invoke" -Method Post -ContentType 'application/json' -Headers $headers -Body $payload
$result | ConvertTo-Json -Depth 20
```

也可用 `tool_id` 指定工具。响应包含 `trace_id`、`cost_micros`、`latency_ms` 和 MCP `result`。工具返回的 `result.isError` 表示业务调用失败，判断成功时同时检查 HTTP 状态和该字段。

## 4. 通过 MCP 调用

```powershell
$mcpHeaders = @{Authorization="Bearer $($login.token)";Accept='application/json, text/event-stream'}
$init = @{jsonrpc='2.0';id=1;method='initialize';params=@{protocolVersion='2025-03-26';capabilities=@{};clientInfo=@{name='demo';version='1.0.0'}}} | ConvertTo-Json -Depth 10
Invoke-RestMethod "$base/mcp" -Method Post -ContentType 'application/json' -Headers $mcpHeaders -Body $init
Invoke-RestMethod "$base/mcp" -Method Post -ContentType 'application/json' -Headers $mcpHeaders -Body '{"jsonrpc":"2.0","method":"notifications/initialized"}'
Invoke-RestMethod "$base/mcp" -Method Post -ContentType 'application/json' -Headers $mcpHeaders -Body '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'
$call = @{jsonrpc='2.0';id=3;method='tools/call';params=@{name='weather_current';arguments=@{city='东莞'}}} | ConvertTo-Json -Depth 10
Invoke-RestMethod "$base/mcp" -Method Post -ContentType 'application/json' -Headers $mcpHeaders -Body $call
```

`tools/list` 按当前用户的有效调用权限过滤，`tools/call` 再检查权限。检查 JSON-RPC `error` 与 `result.isError`；HTTP 200 本身不能证明调用成功。当前协议采用 POST 的 JSON 响应，通知无响应体，不提供完整会话或独立 GET SSE MCP 传输。服务上下线的 SSE 是另一个管理接口。

## 5. 注册原生 MCP Server

```powershell
$server = @{
    name='my-mcp';description='原生 MCP 示例';version='1.0.0'
    endpoint_url='http://mock-mcp:9003/mcp'
    transport='streamable_http';auth_type='none';tags=@('研发')
} | ConvertTo-Json -Depth 10
$registered = Invoke-RestMethod "$base/api/servers" -Method Post -ContentType 'application/json' -Headers $headers -Body $server
Invoke-RestMethod "$base/api/servers/$($registered.id)/sync" -Method Post -Headers $headers
Invoke-RestMethod "$base/api/servers/$($registered.id)/health" -Headers $headers
```

上游地址由网关访问：网关在容器中运行时，`localhost` 指向网关自身。Compose 内使用服务名；Docker Desktop 上访问宿主机服务可使用 `host.docker.internal`。注册后同步获取工具列表。示例只展示无认证的原生服务接入，`auth_type` 字段不代表已经实现完整 OAuth2 授权流程。

## 6. OpenAPI 自动包装

```powershell
$spec = Get-Content -LiteralPath 'specs/weather-v1.json' -Raw | ConvertFrom-Json
$payload = @{spec=$spec;base_url='http://legacy-api:9002'} | ConvertTo-Json -Depth 100
$generated = Invoke-RestMethod "$base/api/servers/generate" -Method Post -ContentType 'application/json' -Headers $headers -Body $payload
$generated.tools | Select-Object id,name,input_schema
```

已有演示服务时，重复导入可能产生名称冲突；可在 `SEED_ON_STARTUP=false` 的空演示环境尝试，或使用自己的规范。`spec` 可为 JSON 对象，也可为 JSON/YAML 文本字符串。`base_url` 是可选的上游地址覆盖；省略时按规范的 servers 选择。具体参数格式及支持范围见 [OpenAPI 兼容性](OpenAPI兼容性与验证.md)。

## 7. 生成独立 Go / TypeScript MCP Server

```powershell
$payload = @{spec=$spec;lang='go';base_url='http://localhost:9002'} | ConvertTo-Json -Depth 100
$project = Invoke-RestMethod "$base/api/wrapper/skeleton" -Method Post -ContentType 'application/json' -Headers $headers -Body $payload
$project.files | ConvertTo-Json -Depth 10
```

`lang` 支持 `go` / `golang` 和 `ts` / `typescript`。响应返回源码文件和运行命令；生成服务在宿主机运行时，上游地址使用宿主机可访问的 URL。保存和启动步骤见 [骨架代码生成与验证](骨架代码生成与验证.md)。

## 8. 导入 Skills

```powershell
$skillMd = "---`nname: report-helper`ndescription: 指导生成订单汇总报表。`n---`n先查询订单，再汇总并保存 Markdown。"
$payload = @{name='report-skills';skill_md=$skillMd} | ConvertTo-Json -Depth 10
$skills = Invoke-RestMethod "$base/api/wrapper/skills" -Method Post -ContentType 'application/json' -Headers $headers -Body $payload
$skills.tools | Select-Object id,name
```

ZIP 导入使用 multipart 字段 `file`；`SKILL.md` 的名称、描述、frontmatter 和目录须符合支持范围。包内资源按需加载，脚本作为资源返回且不会在网关执行。完整示例见 [Skills 导入与资源读取](三项功能实现与验收.md)。

## 9. 接口索引

| 方法 | 路径 | 访问要求 / 用途 |
| --- | --- | --- |
| POST | `/api/auth/login` | 登录，签发 JWT |
| GET | `/health`、`/metrics` | 健康和 Prometheus 指标 |
| GET | `/api/marketplace/tools` | 匿名浏览，q/category/sort/limit |
| GET | `/api/tools/:id`、`/versions`、`/comments` | 匿名读取详情、版本和评论 |
| POST | `/api/tools/:id/rate` | 登录，rating 为 1–5，comment 可选 |
| POST | `/api/tools/:id/connect` | 登录，为当前用户授予调用权限 |
| GET / POST | `/api/servers` | 登录，列表或注册 |
| GET / DELETE | `/api/servers/:id` | 登录，详情或删除 |
| GET | `/api/servers/:id/health` | 登录，手动健康检查 |
| POST | `/api/servers/:id/sync` | 登录，同步原生工具 |
| GET | `/api/servers/events` | 登录，SSE `server.status` 事件 |
| POST | `/api/servers/generate` | 登录，OpenAPI 转工具 |
| POST | `/api/wrapper/skeleton`、`/api/wrapper/skills` | 登录，生成项目或导入 Skills |
| POST | `/api/gateway/invoke`、`/mcp` | JWT、限流、工具调用权限 |
| GET | `/api/stats/summary`、`/daily`、`/top` | 匿名分析读取 |
| GET | `/api/audit/alerts`、`/api/audit/report` | 登录，告警或治理周报 |

表中的 `/versions`、`/comments` 以 `/api/tools/:id` 为前缀，统计的 `/daily`、`/top` 以 `/api/stats` 为前缀。

分析接口的 `X-Analytics-Source` 响应头标明 `clickhouse` 或 `postgres`；ClickHouse 是异步同步，最新调用可能短暂缺席。`X-Trace-Id` 可关联审计与 Jaeger。

## 10. 常见失败

- `401`：JWT 缺失、无效或过期。
- `403`：REST 工具调用权限不足；MCP 调用也可能通过 JSON-RPC 错误表达拒绝。
- `404`：REST 工具或资源未注册。
- `429`：超过默认每用户 20 RPS、突发 40 次的额度。
- 下游失败或熔断：查看返回错误、`result.isError`、网关日志与 trace。

当前管理 API 采用登录校验，自助接入允许登录用户获取工具调用权限。生产场景的管理授权、审批与租户隔离需另行扩展。
