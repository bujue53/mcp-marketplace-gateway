# 开发报告：企业级 MCP 工具市场与智能体网关

## 1. 项目定位与目标

本项目面向「AI 应用开发 / 平台工程」方向，回答一个现实问题：企业内部大量遗留 REST API 与零散的 MCP 工具如何被 Agent 统一发现、安全调用并治理。

核心目标：

1. 统一管理 MCP Server 的注册、发现、版本、权限与审计；
2. 提供工具市场页面（浏览 / 搜索 / 评分 / 一键接入 / 调用统计）；
3. 网关层实现认证鉴权、限流熔断、成本计量与全链路审计；
4. 将 OpenAPI 3.x 规范与遗留 REST API 自动包装为 MCP 工具，解决「工具孤岛」。

## 2. 总体架构

系统采用「注册中心 + 网关 + 工具市场 + 自动包装器」的分层架构：

```text
┌──────────────────────────────────────────────────────────────┐
│  Agent / 测试客户端（MCP Streamable HTTP + JWT）             │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  Agent Gateway（Go + Gin）                                    │
│  · JWT 认证 + RBAC 授权                                       │
│  · Redis 令牌桶限流                                           │
│  · 熔断器（失败比例/探针）                                     │
│  · 成本计量（token 估算 × 单价）                               │
│  · 全链路审计（trace_id + 审计日志 + OpenTelemetry）            │
└───────────────┬──────────────────────────────┬───────────────┘
                │ 元数据/记录                  │ 工具转发
                ▼                              ▼
      ┌──────────────────┐             ┌───────────────┐
      │ PostgreSQL       │             │ Redis         │
      │ 注册/版本/权限/评分│             │ 令牌桶限流    │
      └──────────────────┘             └───────────────┘
                │
                ▼
   ┌────────────────────────────┬─────────────────────────────┐
   │  legacy REST API（OpenAPI） │  mock MCP Server（原生MCP）   │
   │      ↑                     │                             │
   │  OpenAPI → MCP 自动包装器 ──┘                             │
   └────────────────────────────┴─────────────────────────────┘
```

## 4. 核心流程

### 4.1 注册 → 发现

管理员通过 `POST /api/servers` 注册 MCP Server；也可通过 `POST /api/servers/generate` 上传 OpenAPI 文档，系统自动解析并生成 MCP 工具。市场页 `GET /api/marketplace/tools` 支持按名称/描述模糊搜索与分类过滤。

### 4.2 网关鉴权 → 调用

1. 客户端登录换取 JWT（`POST /api/auth/login`）；
2. 携带 `Authorization: Bearer <token>` 调用 `POST /api/gateway/invoke`（REST）或 `POST /mcp`（MCP Streamable HTTP）；
3. 网关依次执行：JWT 校验 → RBAC `invoke` 授权 → Redis 令牌桶限流 → 熔断器放行 → 转发到后端工具；
4. 记录 `tool_calls`（延迟、token、成本）与审计日志，并写入 OTel trace。

### 4.3 成本计量

- 输入 token：对调用参数做字节级估算（`len(arguments)/4`）；
- 输出 token：对工具返回内容文本做同样估算；
- 成本 = `(in+out) * 单价`，单价默认 `$0.002 / 1k tokens`，存入 `tool_calls.cost_micros`。

> 说明：骨架阶段用近似 tokenizer；上生产可替换为真实 tokenizer（如 GPT tokenizer）或后端上报。

## 5. OpenAPI → MCP 自动包装器设计

位置：`gateway/internal/wrapper`。

### 5.1 解析

支持 OpenAPI 3.0/3.1 的 JSON/YAML、各级 `servers`、`operationId`、本地与递归 Schema 引用、公共参数、path/query/header/cookie 参数、请求体、安全方案与响应 Schema。完整支持矩阵与边界见 [OpenAPI兼容性与验证](OpenAPI兼容性与验证.md)。

### 5.2 工具命名

- 优先取 `operationId`，如 `weather_current`；
- 缺失时用 `<method>_<path>` 清洗为合法工具名。

### 5.3 输入 Schema

把 path/query 参数、headers/cookies、认证参数与请求体组合为 MCP 输入 JSON Schema；保留各参数的 required 约束和真实响应 Schema。

### 5.4 运行时绑定（Binding）

每个生成工具保存方法、路径、有效服务器地址、参数位置/序列化、安全方案和请求体媒体类型。调用时重建 REST 请求，并把响应包装为 MCP `content[].text`；绑定持久化到 PostgreSQL，支持网关重启恢复。

### 5.5 已知限制与扩展

- 已支持 JSON/YAML、本地引用与递归 Schema、公共参数、头/cookie、查询数组、JSON/表单/文本请求体、Bearer/API Key 和真实响应 Schema；
- 地址由显式覆盖或 OpenAPI 各级 servers 选择；
- 外部引用、OAuth2、文件上传等高级范围详见 `OpenAPI兼容性与验证.md`。

## 6. 限流与熔断算法

### 6.1 限流：Redis 令牌桶

每个主体（默认用户，兜底 IP）一个桶，容量 `burst`，按 `rps` 每秒补充令牌。脚本原子地补充并扣减：

```lua
tokens = min(capacity, tokens + elapsed * rate)
if tokens >= 1 then allowed=1; tokens=tokens-1 else allowed=0 end
```

超过容量返回 `429` 并带 `Retry-After`。

### 6.2 熔断：状态机

每个工具一个熔断器，状态机 `closed → open → halfOpen → closed`：

- `closed`：统计滑动窗口内失败比例；
- 当样本数 ≥ `minSamples` 且失败比例 ≥ `failRatio`（默认 0.5）→ 进入 `open`；
- `open`：直接拒绝，直到 `interval`（默认 10s）到期；
- 到期进入 `halfOpen`，只放行 1 个探针：成功则回到 `closed`，失败则回到 `open`。

骨架阶段为进程内实现（单实例足够）；接口已抽象，后续可替换为 Redis 共享状态实现多实例一致性。

## 7. 安全设计

- 密码使用 bcrypt 哈希；
- JWT HS256，含 `uid/username/role` 与过期时间；
- RBAC 三默认角色：`admin`（全量）、`developer`（invoke/read/manage）、`viewer`（read）；支持角色/用户级细粒度 `permissions` 覆盖；
- 审计日志记录 `trace_id`、用户、动作、资源、IP、UA。

## 8. 技术选型说明

- Go + Gin：并发性能好、生态成熟，符合网关场景；
- PostgreSQL：注册中心/元数据/审计，使用 pgx；
- Redis：令牌桶限流（原子 Lua）；熔断为网关进程内状态机；
- ClickHouse：异步调用日志分析，保存同步游标、故障补传、重放去重与 PostgreSQL 查询回退；
- OpenTelemetry + Jaeger + Prometheus：全链路追踪与指标；
- React 19 + TypeScript + TailwindCSS：市场前端；
- Python（标准库）实现示例服务，保证零依赖可运行。

## 10. 对照选题文档的增强实现（v1.1）

对照正式选题文档，本轮新增：

- **注册中心健康检查与上下线**：后台巡检每 30s 探测所有 Server 的 `/health`（退化到 MCP `initialize`），掉线自动置为 `offline` 并记录 `last_health_at`；`GET /api/servers/:id/health` 可手动触发。
- **异步调用日志 + 参数摘要**：调用与审计日志批量保存至 PostgreSQL，支持背压和正常退出排空；ClickHouse 导出器保存游标、断线补传并在查询中去重，已完成真实故障恢复验证。
- **评分评论**：`tool_ratings.comment` 落库；`GET /api/tools/:id/comments` 展示，前端可提交评论。
- **一键接入配置片段**：`POST /api/tools/:id/connect` 为当前用户授予调用权限并生成 `mcpServers` 配置 JSON。需替换 JWT 和地址，客户端须支持 HTTP MCP 与自定义请求头，并按具体客户端格式适配。
- **OpenAPI→Go/TS 骨架代码生成**：`POST /api/wrapper/skeleton`，输入 OpenAPI 文档返回 MCP Server 骨架源码（Go / TypeScript 双模板）。
- **Agent Skills→MCP 适配器**：`POST /api/wrapper/skills` 接收 JSON、SKILL.md 或 ZIP，验证 frontmatter 和包路径，保留元数据与资源，支持按需加载和重启恢复。
- **异常告警与治理周报**：`audit_alerts` 表 + `GET /api/audit/alerts`；敏感工具高频调用检测 + `GET /api/audit/report`（服务/工具/敏感工具/调用/成本/近 7 天告警）。
- **分类浏览**：新增「数据库 / 办公 / 研发 / 营销」分类，并在市场页筛选。
- **3 个示例 MCP Server**：`mock-weather-mcp`（原生）、`mock-file-server`（文件）、`mock-db-server`（数据库），加上 OpenAPI 自动包装的 legacy 服务共 4 类。
- **权限测试与压测**：已验证敏感工具 20/20 次拒绝并留审计、暖缓存后的即时权限撤销、真实数据库到报表任务，以及 2000 QPS 和 P99 网关开销目标；完整结果见 `最终三项验收结果.json` 与 `性能验收报告.md`。
