# Skills、ClickHouse 与性能验收

## 1. Agent Skills 规范包

`POST /api/wrapper/skills` 支持三种输入：原有 `skills` JSON 数组、`skill_md` 文本、multipart 的 `file`（SKILL.md 或 ZIP）。可选 `name` 指定注册服务名称。

ZIP 示例：

```text
report-agent/
  SKILL.md
  references/guide.md
  scripts/render.py
  assets/template.md
```

```yaml
---
name: report-agent
description: 查询数据并生成报表，适用于订单汇总。
license: MIT
metadata:
  author: project32
allowed-tools: acceptance_query acceptance_report_write
---
先查询数据库，再生成并保存 Markdown 报表。
```

解析 YAML frontmatter、目录名、名称与描述约束，并保留可选元数据；规则依据 [Agent Skills 官方格式](https://agentskills.io/specification)。导入包最多 16 MiB、256 项，单文件最多 1 MiB、解压内容最多 32 MiB；拒绝路径越界、重复路径、符号链接、孤立文件与嵌套技能目录。资源在内存解析后保存至 PostgreSQL；不在服务器上直接执行包内脚本。

在 PowerShell 7 中导入：

```powershell
$login = Invoke-RestMethod 'http://localhost:8080/api/auth/login' -Method Post -ContentType 'application/json' -Body '{"username":"admin","password":"admin123"}'
$headers = @{Authorization="Bearer $($login.token)"}
Invoke-RestMethod 'http://localhost:8080/api/wrapper/skills' -Method Post -Headers $headers -Form @{name='report-skills';file=Get-Item '.\report-skills.zip'}
```

生成的 MCP 工具名为 `skill_<name>`。空参数加载说明与资源目录；`{"resource":"references/guide.md"}` 按需读取包内资源，返回 `encoding` 与 `content`。文本使用 UTF-8，二进制使用 Base64。`allowed-tools` 是交给客户端的声明，调用权限由网关 JWT/RBAC 决定。映射支持重启恢复，内部技能服务健康检查不会访问不存在的 HTTP 地址。

## 2. ClickHouse 调用分析

Compose 已加入真实 ClickHouse 服务及数据卷。配置项为 `CLICKHOUSE_URL/USER/PASSWORD/DATABASE`，默认 HTTP 端口 8123。接口使用认证的 [ClickHouse HTTP 协议](https://clickhouse.com/docs/concepts/features/interfaces/http)。

调用日志先通过有背压的队列批量写入 PostgreSQL；独立导出器每 250ms 按已提交记录同步到 ClickHouse，确认写入后推进数据库游标。ClickHouse 断开时网关继续调用并保存日志，恢复后补传。重启可恢复游标；重放记录通过 ReplacingMergeTree 与查询 `FINAL` 去重。该实现用于本项目的单网关实例，未宣称多写入实例的分布式提交顺序或严格恰好一次语义。

调用日志和审计日志使用批量事务写入，处理实体在排队期间被删除的情况；中文参数摘要按 UTF-8 边界截断。正常退出会排空队列。日志尚在内存中时的强制进程终止、PostgreSQL 不可用期间的强制退出仍可能丢失未提交批次。

以下接口优先从 ClickHouse 查询，故障时使用 PostgreSQL，响应头 `X-Analytics-Source` 标明来源：

| 接口 | 结果 |
| --- | --- |
| `/api/stats/summary` | 调用次数、成本、异常数量、工具调用 P99 时延，服务/工具数量来自注册中心 |
| `/api/stats/daily` | 按上海时区统计每日调用量 |
| `/api/stats/top` | 调用量排行，保持现有前端工具字段 |
| `/api/audit/report` | 治理摘要、最近 7 天调用分析与敏感工具告警 |

ClickHouse 数据是异步同步的，查询可能暂时落后于最新调用。敏感工具高频告警继续依据 PostgreSQL 中的已保存记录触发。

## 3. 性能与真实 Agent 任务

验收专用 MCP 服务提供高速转发工具、真实 PostgreSQL 只读查询及报表写入/读回工具。自研工作流 Agent 先加载技能，通过网关查询真实订单数据，再生成 Markdown 报表、调用文件工具保存并读回比较；验收数据为 3 行、合计 700。流程由规则驱动，未调用外部大模型。

压测客户端采用固定速率、连接复用和完整响应校验；只有 HTTP 200、JSON-RPC 2.0、无协议错误且 `isError=false` 的调用计入成功吞吐量。核对所有完成请求和预热请求均写入 PostgreSQL，随后与 ClickHouse 去重数量比较。

每个请求的网关开销取网关处理耗时减去该请求下游 HTTP 调用至响应体读完的时间，由响应 trailer `X-Gateway-Overhead-Ms` 返回。包含 JWT、RBAC、Redis 限流、路由、序列化和异步日志提交；端到端客户端时延单独记录，不能用它替代网关开销。

优化包括共享下游连接池、避免调用路径扫描历史统计、500ms 元数据缓存与合并刷新、日志批量写入。权限覆盖仍每次查询 PostgreSQL，已验证暖缓存后的即时撤销。身份、角色及服务配置直接从数据库修改时，缓存最多延后 500ms；应用内工具与服务更新会主动失效缓存。

验收配置将单用户限流额度设为 5000 RPS，关闭控制台逐请求文本日志；JWT/RBAC、Redis、熔断、完整 OTel 追踪、业务审计和成本计量均保持启用。默认业务限流仍为 20 RPS。

## 4. 复验

在项目根目录执行：

```powershell
docker compose -f docker-compose.yml -f deploy/compose.acceptance.yml up --build -d gateway acceptance-backend
node tools/verify-final.mjs
```

脚本会重启网关、暂时停止并恢复 ClickHouse、重置导出游标进行重放，并创建验收账号、技能、订单表和报表。最终结果写入 `最终三项验收结果.json`；性能数字及口径见 `性能验收报告.md`。本轮通过后执行整体数据清理，结果见 `数据清理结果.json`。

后端测试：在 `gateway` 目录执行 `go test ./...`。清理并停止整个项目：

```powershell
.\tools\clear-data.ps1 -ConfirmClear
```

清理脚本先检查验收全部通过，再验证 Docker 项目与当前工作区一致，删除项目容器及运行数据卷。代码、镜像和验收文档保留。清理后启动基础服务：

```powershell
docker compose up --build -d
```

启动会重新执行迁移并创建基础 admin/dev 账号；`SEED_ON_STARTUP=false` 时不自动恢复示例工具。需要示例时手动执行 `docker compose exec gateway ./bin/ctl seed`。
