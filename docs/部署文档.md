# 部署文档

## 1. 前置要求

- Docker Desktop（Linux 容器）或 Docker Engine，Docker Compose v2。
- 首次构建可联网拉取镜像、Go 和 npm 依赖。
- 网关、前端和基础设施映射端口空闲，详见下表。
- 本次完整性能验收使用 Docker 的 16 个 CPU、约 7.37 GiB 内存；资源需求随实际负载变化。

Docker 部署不要求宿主机安装 Go/Node.js。客户端演示需要 Python 3；综合验收脚本需要 Node.js 22+。

## 2. 服务组件

| 服务 | 来源 | 宿主机端口 | 用途 |
| --- | --- | --- | --- |
| gateway | Go 本地构建 | 8080 | 注册中心、网关、MCP 与包装器 |
| web | React 本地构建 | 5173 | 工具市场 |
| postgres | postgres:16-alpine | 5432 | 元数据、权限、调用与审计日志 |
| redis | redis:7-alpine | 6379 | 令牌桶限流 |
| clickhouse | clickhouse/clickhouse-server:25.8 | 8123 | 调用日志分析 |
| jaeger | jaegertracing/all-in-one:1.57 | 16686、4317、4318 | 追踪查看与 OTLP 接收 |
| prometheus | prom/prometheus:v2.52.0 | 9090 | 指标采集 |
| legacy-api | Python 本地构建 | 9002 | 遗留 REST 天气服务 |
| mock-mcp | Python 本地构建 | 9003 | 原生天气 MCP |
| mock-file | Python 本地构建 | 9004 | 原生文件 MCP |
| mock-db | Python 本地构建 | 9005 | 原生数据库 MCP |

熔断在网关进程内实现。PostgreSQL 和 ClickHouse 使用数据卷；默认 Redis 关闭持久化。

## 3. 初始化与启动

在仓库根目录执行：

```powershell
# Windows
Copy-Item .env.example .env
docker compose up --build -d
docker compose ps
docker compose logs --tail 50 gateway
```

Linux/macOS 使用 `cp .env.example .env` 后执行相同的 Docker 命令。已有 `.env` 时先保留自己的配置，避免覆盖。

网关启动时自动执行 migrations 并创建基础账号。日志出现 `gateway listening` 后访问：

- 工具市场：http://localhost:5173
- 健康检查：http://localhost:8080/health
- Jaeger：http://localhost:16686
- Prometheus：http://localhost:9090

初次拉取和构建耗时取决于网络；`docker compose ps` 中的依赖服务应为 healthy，网关为 running。Compose 没有给 gateway 配置 Docker healthcheck，网关状态可通过 `/health` 检查。

## 4. 配置说明

| 变量 | 演示默认值 / 作用 |
| --- | --- |
| COMPOSE_PROJECT_NAME | mcp-marketplace；验收脚本和清理脚本使用此名称 |
| POSTGRES_USER / PASSWORD / DB | mcp / mcp-secret / mcp_market |
| DATABASE_URL | PostgreSQL 连接串；密码须与 POSTGRES_PASSWORD 一致 |
| REDIS_ADDR / PASSWORD / DB | Redis 连接；默认 redis:6379、无密码、DB 0 |
| JWT_SECRET / JWT_TTL_HOURS | 演示密钥 / 24 小时 |
| ADMIN_USER / ADMIN_PASS | admin / admin123 |
| RATE_LIMIT_RPS / BURST | 20 / 40，每用户令牌桶 |
| CIRCUIT_FAIL_RATIO / MIN_SAMPLES | 0.5 / 10，滑动窗口失败比例阈值 |
| CIRCUIT_INTERVAL / WINDOW | 10s / 30s，探针等待与统计窗口 |
| COST_PER_1K_TOKENS | 0.002，估算成本单价 |
| CLICKHOUSE_URL / USER / PASSWORD / DATABASE | http://clickhouse:8123 / mcp / mcp-analytics / mcp_market |
| OTEL_EXPORTER_OTLP_ENDPOINT | jaeger:4318，使用 HTTP/protobuf |
| SEED_ON_STARTUP | 模板为 true，注册示例服务和 OpenAPI 工具 |
| VITE_API_BASE | http://localhost:8080，前端构建时注入 |
| HTTP_REQUEST_LOG | 未设置时 true；验收配置关闭逐请求控制台日志 |

默认账号和密码用于本机演示，创建的开发者账号为 `dev / dev123`。修改管理员变量不会自动重置已有数据库账号。模板里声明的 DEV_USER/DEV_PASS 当前未被后端读取；需要不同开发者凭据时修改账号管理实现或数据库中的密码哈希。

修改数据库、ClickHouse 密码时应同时修改连接配置；已有数据卷的数据库账号不会因为修改环境变量自动重建。修改 VITE_API_BASE 后需重新构建 web 镜像。

`SEED_ON_STARTUP=false` 只关闭示例业务数据初始化，启动仍会迁移并创建基础 admin/dev 账号。需要示例工具时执行：

```bash
docker compose exec gateway ./bin/ctl seed
```

## 5. 访问和调用

前端登录后可以评分评论、接入工具、查看版本和统计。Agent 客户端使用 Python 标准库：

```bash
python agents/mcp_client.py --list
python agents/mcp_client.py --mcp --tool weather_current --args '{"city":"东莞"}'
python agents/mcp_client.py --rest --tool weather_forecast --args '{"city":"深圳","days":2}'
```

JSON 命令适用于 Bash 或 PowerShell 7.3+；其他 PowerShell 版本请用[接口使用说明](接口使用说明.md)中的对象序列化示例。调用经过 JWT、权限判断、Redis 限流、熔断、转发、计量和审计，可用 trace ID 在 Jaeger 查看。

## 6. 启停和清理

```bash
docker compose logs -f gateway
docker compose exec gateway ./bin/ctl migrate
docker compose down
```

`down` 保留数据卷，下一次启动恢复数据。完整复验命令和有范围校验的数据清理脚本见[三项功能实现与验收](三项功能实现与验收.md)。

完整验收通过后，在项目根目录用 PowerShell 执行：

```powershell
.\tools\clear-data.ps1 -ConfirmClear
```

这会停止当前工作区的项目容器并删除数据库、分析和验收报表卷，同时将本地 `.env` 的 SEED_ON_STARTUP 设为 false。代码、镜像、文档保留；不是仅清除测试账号。清理前应确认没有需要保留的业务数据。记录见[数据清理结果](数据清理结果.json)。

## 7. 本地开发

需要 Go 1.26+、Node.js 22+ 和 Python 3。先启动依赖：

```bash
docker compose up -d postgres redis legacy-api mock-mcp mock-file mock-db
```

本地网关不自动加载根目录 `.env`，需要将配置设置为进程环境变量。PowerShell 示例（使用演示默认数据库密码）：

```powershell
$env:DATABASE_URL='postgres://mcp:mcp-secret@localhost:5432/mcp_market?sslmode=disable'
$env:REDIS_ADDR='localhost:6379'
$env:LEGACY_API_URL='http://localhost:9002'
$env:MOCK_MCP_URL='http://localhost:9003'
$env:MOCK_FILE_URL='http://localhost:9004'
$env:MOCK_DB_URL='http://localhost:9005'
$env:SEED_ON_STARTUP='true'
$env:CLICKHOUSE_URL=''
$env:OTEL_EXPORTER_OTLP_ENDPOINT=''
cd gateway
go run ./cmd/ctl serve
```

Linux/macOS 使用 `export VARIABLE=value` 设置同名变量。另开终端在项目根目录运行：

```bash
cd web
npm install
npm run dev
```

本地未配置 ClickHouse 时使用 PostgreSQL 分析。若要启用，先启动 clickhouse 并设置 localhost:8123 地址及认证；启用追踪同理启动 jaeger 并设置 localhost:4318。

## 8. 验收和故障排查

[性能验收报告](性能验收报告.md)给出实际环境和结果；[最终三项验收结果](最终三项验收结果.json)提供机器记录。复验会创建测试数据、重启网关并暂时停止/恢复 ClickHouse，在专用演示环境执行。

| 现象 | 排查方法 |
| --- | --- |
| 端口冲突 | 检查上表端口占用；修改 Compose 映射与客户端访问地址 |
| 网关无法启动 | 查看 gateway 日志、postgres/redis 健康状态与连接密码 |
| 工具列表为空 | 检查示例初始化日志；需要示例时执行 ctl seed |
| 前端无法访问 API | 查看 VITE_API_BASE；部署到其他机器时不能继续使用浏览器的 localhost |
| 调用返回 429 | 默认限额为 20 RPS；检查用户请求速率与突发量 |
| Jaeger 没有 trace | 检查 jaeger 服务、OTLP 地址和调用是否实际发生 |
| 分析源变为 postgres | 检查 ClickHouse 网络、账号和导出器日志；恢复后等待补传 |

## 9. 部署边界

Compose 面向本机演示，默认向宿主机映射多个基础设施端口。部署到外部网络时，应限制端口暴露、配置 HTTPS 反向代理、替换默认密钥和账号。当前匿名市场/统计读取、登录后服务管理与自助接入权限模型，适合受信任演示用户；生产管理授权、审批和租户隔离需扩展。单实例状态、日志内存队列和 OpenAPI 支持范围见[项目首页](../README.md#当前边界)。
